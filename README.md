# Сканер ожини (прототип)

Вебзастосунок, який за фото лотка зі свіжою ожиною орієнтовно оцінює якість партії та формує PDF-звіт.
Усе рахується в браузері на пристрої: фото нікуди не надсилаються, сервер не потрібен.

> Це демо. Відсотки — частка **площі видимої поверхні** на фото, а не маси чи кількості ягід.
> Пороги вердикту — **демо-значення, їх треба уточнити з технологом**. Оцінка не є лабораторним висновком.

## Що вміє

- одне або кілька фото партії (камера телефона чи файл);
- категорії: якісні (темні), недостиглі/червоні, зелені, пліснява, рослинні домішки;
- фото з кольоровим шаром категорій і теплова карта дефектів;
- вердикт: придатна для заморожування після сортування / для переробки / відхилити;
- рівень впевненості та позначка «Потрібна перевірка людиною»;
- PDF-звіт українською;
- історія партій на пристрої (IndexedDB);
- «Виправити результат»: фото й виправлення оператора зберігаються локально, експорт усього в ZIP для майбутнього навчання;
- налаштування порогів;
- працює без інтернету після першого відкриття (PWA).

## Як запустити

- **Найпростіше:** двічі клацнути `index.html`. Працює все, крім офлайн-кешу та кнопки «Спробувати на демо-фото»
  (браузер не дає сторінці-файлу читати сусідні файли).
- **Як на сервері:** `node tools/serve.js`, далі відкрити http://localhost:8765.

## Як знімати

- зверху, щоб ягоди займали майже весь кадр; край лотка і стіна в кадрі допустимі, але що їх менше, то краще;
- рівне світло, без спалаху; по змозі те саме місце й та сама лампа;
- якщо програма неправильно визначила, де ягоди, — кнопка «Уточнити зону» на екрані результату.

## Розгортання на Cloudflare Pages (безкоштовно)

Назви кнопок на сайтах можуть трохи відрізнятися — орієнтуйтеся на зміст.

### 1. Обліковий запис GitHub і репозиторій

1. Відкрийте https://github.com → **Sign up**, зареєструйтеся і підтвердіть пошту.
2. Угорі праворуч **+ → New repository**.
3. Назва: `berry-scanner`. Тип: **Private**. Нічого більше не вмикайте. **Create repository**.
4. Скопіюйте адресу репозиторію зі сторінки, що відкрилася (вигляду `https://github.com/ВАШЕ_ІМ'Я/berry-scanner.git`).

### 2. Надіслати код

У цій папці вже є локальний репозиторій git із першим комітом. Відкрийте термінал у папці проєкту й виконайте,
підставивши свою адресу:

```bash
git remote add origin https://github.com/ВАШЕ_ІМ'Я/berry-scanner.git
```

```bash
git push -u origin main
```

Під час першого `push` відкриється вікно входу в GitHub — увійдіть. Після цього файли з'являться на сторінці репозиторію.

### 3. Обліковий запис Cloudflare і проєкт Pages

1. Відкрийте https://dash.cloudflare.com/sign-up, зареєструйтеся і підтвердіть пошту. Платіжна картка не потрібна.
2. У меню ліворуч: **Workers & Pages → Create** (або **Create application**) → вкладка **Pages**.
3. **Connect to Git** (або **Import an existing Git repository**) → **GitHub** → дозвольте доступ до репозиторію `berry-scanner` → виберіть його → **Begin setup**.
4. Налаштування збірки:
   - **Project name:** наприклад `berry-scanner` — це буде частина посилання;
   - **Production branch:** `main`;
   - **Framework preset:** `None`;
   - **Build command:** залишити порожнім;
   - **Build output directory:** `/`.
5. **Save and Deploy**. За хвилину з'явиться посилання вигляду `https://berry-scanner.pages.dev`.

Без GitHub теж можна: на вкладці **Pages** виберіть **Upload assets** і перетягніть туди папку проєкту.
Але тоді кожне оновлення доведеться завантажувати вручну.

### 4. Відкрити на планшеті чи телефоні

1. Відкрийте посилання в Chrome на Android.
2. Меню **⋮ → Додати на головний екран** (або **Встановити додаток**) — з'явиться іконка.
3. Після першого відкриття застосунок працює без інтернету.

### 5. Оновлення

1. Змініть файли.
2. Підніміть версію **у двох місцях**: `APP_VERSION` у `js/core/defaults.js` і `VERSION` у `sw.js`
   (тест `tests/pwa.test.js` перевіряє, що вони збігаються). Без цього пристрої показуватимуть стару версію з кешу.
3. `git add -A`, `git commit -m "..."`, `git push` — Cloudflare сам розгорне нову версію.
4. На пристроях з'явиться смужка «Доступна нова версія» з кнопкою «Оновити».

### Що буде видно за посиланням

Сайт на `pages.dev` відкритий для всіх, хто знає посилання, навіть якщо репозиторій приватний.
За посиланням доступні всі файли репозиторію, зокрема демо-фото `data/samples/…` і приклад звіту `docs/…`.
Якщо це небажано, приберіть ці файли перед розгортанням (кнопка демо-фото тоді не працюватиме)
або закрийте сайт через Cloudflare Access (**Settings → Access policy** у проєкті Pages).
Фото, які знімають користувачі, за посиланням **не** доступні: вони лишаються на пристрої.

## Як це працює (v0, без навчання моделі)

1. Фото зменшується до 1024 px по довшій стороні.
2. Баланс білого оцінюється за нейтральними світлими пікселями й обережно виправляється.
3. **Зона ягід.** Біла стіна і біла пліснява мають однаковий колір, тому спершу шукається темна маса ягід
   (груба сітка, змикання, найбільша зв'язна область), і лише всередині неї йде класифікація. Синій лоток виключається за кольором.
4. Кожен піксель зони за HSV відноситься до категорії. Яскравість нормується за медіаною зони.
5. Світлі нейтральні плями діляться за розміром: дрібні — блики, більші — пліснява. Біле на межі зони вважається тлом.
6. Рахується частка площі кожної категорії, вердикт за порогами та впевненість.

Впевненість — це не статистична точність, а сума штрафів: мала зона ягід, темне, пересвічене чи нечітке фото,
багато бліків, багато «сірих» ділянок, сильний відтінок освітлення, результат біля порога, розбіжність між фото.

### Відомі обмеження

- тонкий сірий наліт плісняви не відрізняється від розсіяного відблиску, тому **відсоток плісняви — нижня оцінка**;
- видно лише верхній шар; фото під кутом завищує вагу ближніх ягід;
- межа «зелене / коричневе» чутлива до освітлення й камери;
- роздавлені та пошкоджені ягоди за кольором не визначаються;
- пороги кольорів підібрано на одному фото — на інших камерах і лампах їх, імовірно, доведеться підправити
  (Налаштування → «Розпізнавання кольорів»), а надалі замінити навченою моделлю на зібраних виправленнях.

## Структура

```
index.html              сторінка (звичайні скрипти, без збірки)
manifest.webmanifest, sw.js, _headers   PWA і заголовки Cloudflare
css/app.css
js/core/                логіка без DOM: defaults (версії, пороги), segment (сегментація), verdict (вердикт, впевненість)
js/io/                  image (декодування, шар на фото), db (IndexedDB), pdf (звіт), export (ZIP)
js/ui/                  app (каркас, нова партія), result (результат, зона, виправлення), history, settings
vendor/                 jsPDF, fflate, шрифт Noto Sans (підмножина) та їхні ліцензії
icons/
tests/                  тести: node --test tests/
tools/                  analyze.js (сегментація з командного рядка), serve.js (локальний сервер)
data/samples/           зразок фото
docs/                   приклад звіту сторонньої моделі (лише орієнтир оформлення)
```

## Перевірка

```bash
node --test tests/
```

Тести (потрібен лише Node 18+, без встановлення пакетів): синтетичні сцени (блик не є пліснявою, стіна не потрапляє в зону,
кольори категорій), пороги вердикту, зразок фото (30 контрольних точок, діапазони часток), стійкість до яскравості,
відтінку світла, розміру й повороту, цілісність офлайн-кешу.

Подивитися, що алгоритм бачить на фото:

```bash
node tools/analyze.js data/samples/photo_2026-11-12_18-39-37.jpg --out overlay.png
```

## Формат експорту

ZIP містить `export.json` і `photos/<id>.jpg`. У `export.json` для кожної партії: дані партії, налаштування на момент оцінки,
версія алгоритму, результат по кожному фото (`photos[].summary.percents`), зведення (`evaluation`) і виправлення оператора
(`correction`: частки, вердикт, коментар) або `null`.
